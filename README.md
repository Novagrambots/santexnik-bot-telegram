# Santexnik Bot

Telegram-бот для сантехнической компании: напоминания о профилактике оборудования, заявки на мастера, рассылки и админ-панель.

## Возможности
- Самостоятельная регистрация клиента (имя, телефон, язык ru/uz).
- Несколько единиц оборудования на клиента, у каждой своя дата и период профилактики.
- Автоматические напоминания за 14 / 3 / 0 дней с кнопками «Записаться / Уже сделал / Перенести».
- Заявки: вызов мастера и аварийная заявка (уходят админам).
- Админ-панель: список клиентов, карточка, ручное изменение даты, статистика, экспорт в Excel, обработка заявок.
- Мастера по видам оборудования: заявка «Записаться» с напоминания уходит мастеру этого вида + супер-админам (супер-админы уведомляются всегда, даже если мастера нет).
- Рассылка по сегментам (все / просроченные / по языку / по виду оборудования) с отчётом о доставке.

## Стек
aiogram 3, SQLAlchemy (async) + PostgreSQL (asyncpg), APScheduler, pydantic-settings, openpyxl.

## Запуск в Docker (рекомендуется)
```bash
cp .env.example .env   # вписать BOT_TOKEN и ADMIN_IDS
docker compose up --build -d
```
Поднимаются два сервиса: `db` (PostgreSQL 16) и `bot`. Данные БД — в томе `pgdata`.
Бот дожидается готовности БД (healthcheck + ретрай подключения), таблицы создаются автоматически.

## Запуск (локально)
Нужен доступный PostgreSQL. Пропишите `DB_URL` в `.env`, затем:
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN, ADMIN_IDS, DB_URL
python bot.py
```
Для быстрой локальной разработки без Postgres можно временно указать SQLite:
`DB_URL=sqlite+aiosqlite:///data/santexnik.db` (драйвер `aiosqlite` уже в зависимостях).

## Настройки (.env)
- `BOT_TOKEN` — токен от @BotFather.
- `ADMIN_IDS` — id админов через запятую.
- `REMINDER_HOUR` / `REMINDER_MINUTE` — время ежедневной проверки напоминаний.
- `REMINDER_STAGES_DAYS` — этапы напоминаний (по умолчанию `14,3,0`).

## Команды админа
- `/admin` — панель (клиенты, статистика, заявки, рассылка, экспорт, ⚙️ настройки).
- `/test_reminders` — принудительно прогнать проверку напоминаний (для теста).

## Миграции БД (Alembic)
Схема БД управляется Alembic. При старте бот сам накатывает все миграции
(`alembic upgrade head`) — отдельно ничего запускать не нужно, данные не теряются.

Создать новую миграцию после изменения моделей в `db/models.py` (через Docker):
```bash
docker compose run --rm bot alembic revision --autogenerate -m "описание изменения"
docker compose restart bot   # применит новую миграцию при старте
```
Ручное применение/откат:
```bash
docker compose run --rm bot alembic upgrade head
docker compose run --rm bot alembic downgrade -1
```

## Настройки напоминаний
Время ежедневной проверки и этапы (за сколько дней слать) редактируются прямо в
админке: `/admin` → ⚙️ Настройки. Значения хранятся в БД; при смене времени задача
планировщика пересоздаётся на лету, без перезапуска бота. `REMINDER_*` в `.env` —
только стартовые значения для первого запуска с пустой БД.
